# QA 报告 — 视觉 + 功能全量检查（2026-10-30）

> 范围：`dist/client/` 静态导出的全部 43 个 route + 1 个不存在的 URL（404）。**只做报告，不改应用代码。**
> 构建：`npm ci` → `NEXT_PUBLIC_SITE_URL=https://www.firstrec.work npm run build`（exit 0，43 个 `index.html` + `404.html`）。未设置 `NEXT_PUBLIC_CONTACT_EMAIL`，所以页面里的邮箱是缺省值 `hello@cheese.studio`。
> 环境：Linux 容器，Node v22.22.0，Playwright 预装 Chromium（headless）。**只测了 Chromium**，没有 Firefox / WebKit / 真机。

## 0. 方法

- **Static server**：自写的 Node 静态服务器，尽量模拟 nginx：文件存在直接返回；目录无尾斜杠 → 301 到带斜杠；目录 → `index.html`；找不到 → 返回 `404.html` + HTTP 404。⚠️ 生产 nginx（`compose.truenas.yaml`）**并没有**配置 `error_page 404 /404.html`，见 M2。
- **Viewport**：1440×900（desktop）和 390×844（mobile，`isMobile` + `hasTouch`），DPR 1。
- 每个 route × viewport：先逐屏滚动触发 lazy image，再等 `networkidle` + 1.8s 让入场动画结束，然后做 full-page screenshot 和 DOM 审计：
  - console `error`/`warning`、`pageerror`、HTTP ≥ 400 / `requestfailed` 的请求
  - 390 宽下 `scrollWidth > clientWidth`（横向溢出），并定位最外层越界元素
  - 每个 `<img>`：`naturalWidth`（是否 broken）、computed `object-fit`、自然比例 vs 盒子比例（变形 / 裁切）
  - `alt` 缺失 / 为空；`h1–h6` 顺序（跳级、h1 数量）
  - 所有 `<a href>`：内部链接逐个请求（不跟随 redirect），hash 链接核对目标 `id` 是否存在
  - mobile 下可交互元素（`a, button, summary, input, video…`）尺寸 < 44px
  - 用 init script 拦截 `addEventListener`，统计 `scroll` / `wheel` listener 数
- **`prefers-reduced-motion: reduce`**：在 `/`、`/work/`、`/work/nvidia/`、`/about/`、`/contact/` × 两个 viewport 上，load 后立刻读 `document.getAnimations()` 和关键元素的 computed `animation` / `opacity`。
- 共 98 次页面加载（44 × 2 viewport + 10 次 reduced-motion）。截图共 99 张，只提交了 12 张最有信息量的到 `docs/qa-screenshots/`。
- 另外跑了 `npm run lint` 和 `NEXT_PUBLIC_SITE_URL=https://www.firstrec.work npm test`（见第 5 节）。

## 1. 结论速览

- **真正的 bug（与缺素材无关）**：1 个 mobile 横向溢出（CHIMICHURI 标题）、Molly Tea 视频格式在 Chromium 下不可播放、404 页面未品牌化且生产 nginx 很可能根本不用它、mobile 导航 / CTA 的 tap target 偏小、案例正文整段用 `<h2>`。

## 4. 问题列表（按严重度排序）

### High

**H1. 首页 hero 使用未授权案例图，并对外显示内部审核提示**
- Route / viewport：`/`，desktop + mobile（首屏）
- 现象：hero 图取 `caseStudies[0].image`（Geely，未授权）。本仓库构建下首屏是 broken image + alt 文字；从 Mac 构建时则会把一张“publication clearance pending”的图放在首页首屏。figcaption 直接写着 “Internal review asset / Publication clearance pending”。同一个 Geely 卡片也是 `/work/` 首条。
- 截图：`01-home-desktop-fold-broken-hero.jpg`、`02-home-mobile-menu-open.jpg`
- 建议：`app/page.tsx:23-25` 改为显式指定一个已授权案例的图（如 NVIDIA / Spin Panda），按 slug 取而不是 `caseStudies[0]`；figcaption 去掉内部审核文案。属于 U2（slug 引用）+ U3（发布状态）范围。

**H2. Molly Tea 影片是 QuickTime `.mov`，Chromium 系浏览器无法播放**
- Route / viewport：`/work/molly-tea/`，两个 viewport
- 现象：`<source src="/portfolio/molly-tea/opening-film.mov" type="video/quicktime">`；实测 Chromium `canPlayType('video/quicktime') === ""`，浏览器根本没有请求该文件，播放器只剩 0:00 的空条。**即使把文件从 Mac 拷回来**，Chrome / Edge / Android（以及多数 Firefox）也不会播放；只有 Safari 可能播。文件本身 109 MB，也远大于其他网页视频。
- 截图：`05-molly-tea-film-quicktime.jpg`
- 建议：转码为 H.264/AAC MP4（并压到与其他片子相近的体积），改 `app/_data/site.ts:99-102` 的 `src` 和 `type`（`video/mp4`）。如需保留 `.mov`，至少在其前面加一个 MP4 `<source>`（`app/_components/CaseStudyPage.tsx:42` 目前每个 film 只渲染一个 `<source>`）。

### Medium

**M1. CHIMICHURI 案例页 mobile 横向溢出 19px**
- Route / viewport：`/work/chimichuri/`，390×844
- 现象：`scrollWidth` 409 > 390。越界元素是 `.case-hero` 里的标题容器和 summary 段落（right = 409）。原因：mobile 下 `.case-hero h1 { font-size: 17vw }`，单个长单词 “CHIMICHURI” 无法换行，撑宽了 grid 列，连带下面的段落也被撑宽、右侧被裁。其他 35 个案例名在 390 宽下没有溢出，但更窄的设备（360/375）或更长的单词名会复现。
- 截图：`03-chimichuri-mobile-h1-overflow.jpg`
- 建议：`app/globals.css:300` 把字号改为 `clamp(2.75rem, 14vw, 4.4rem)` 一类的上限，并给 `.case-hero > div` 加 `min-width: 0`、给 `h1` 加 `overflow-wrap: anywhere`（或 `hyphens: auto`）作为兜底。修完建议在 360px 宽再回归一次所有案例标题。

**M2. 404 页面未品牌化；生产 nginx 很可能不会使用它**
- Route / viewport：任意不存在的 URL，两个 viewport
- 现象：`404.html` 是框架默认的 “404 | This page could not be found.”，没有 header / footer / `<main>` / 回首页链接，字体和配色与站点不一致。
- 另外（**仅读配置推断，未实测 Docker**）：`compose.truenas.yaml` 用的是 `nginx:1.27-alpine` 默认配置，默认 `default.conf` 里 `error_page 404 /404.html` 是注释掉的，所以线上很可能返回 nginx 自带的 404 页面，而不是 `dist/client/404.html`。
- 截图：`04-404-desktop-unbranded.jpg`
- 建议：新增 `app/not-found.tsx`（用 `PageShell` + 一句说明 + 回 `/` 和 `/work/` 的链接）；部署侧增加自定义 nginx conf（`try_files $uri $uri/ =404; error_page 404 /404.html;`）挂进 `compose.truenas.yaml`，部署后实测。

**M3. Mobile tap target 偏小（< 44px）**

| 元素 | 实测尺寸 | 出现范围 |

**M4. 对外页面直接展示内部审核文案**
- Route / viewport：首页 + 30 个未授权案例页 + `/work/`，两个 viewport
- 现象：`mediaNotice`（如 “Internal review assets / Project details and publication clearance pending”）在 lead image 角标和影片区标题旁可见；部分案例正文写着 “The approved Drive folder is indexed…”、“publication permissions remain unconfirmed” 等内部语言（例：`/work/chimichuri/`）。已授权案例也显示 “Public display authorised / Project details and credits to confirm”。这不是渲染 bug，但上线即对外可见。
- 建议：U3 发布状态做完后，未授权案例不进入公开构建；已授权案例把 `mediaNotice` 改成面向访客的文案或不渲染（`app/_data/site.ts` 37 处 `mediaNotice`，`app/_components/CaseStudyPage.tsx:17,35`，`app/page.tsx:25`）。

### Low

**L1. 案例正文整段用 `<h2>`**
- 所有 36 个案例页：`.case-story` 里 Context / Response / Value 的长段落（2–4 句）是 `<h2>`，而 “01 / Context” 标签反而是 `<p>`。屏幕阅读器的 heading 导航会读出整段文字，结构语义颠倒。Heading 顺序本身没有跳级。
- 建议：`app/_components/CaseStudyPage.tsx:26-28` 把 “01 / Context” 等改成 `<h2>`、正文改成 `<p>`，在 `app/globals.css:141` 附近保留现有大字号样式。

**L2. Mobile 菜单的可访问性细节**
- `<summary aria-label="Open navigation">Menu</summary>`：`aria-label` 覆盖了可见文字 “Menu”（WCAG 2.5.3 Label in Name），展开后仍叫 “Open navigation”。实测按 Esc、点击菜单外部都**不会**关闭菜单（`<details>` 原生行为）；点链接后是整页跳转，所以新页面上菜单是关闭的（正常）。
- 建议：`app/_components/SiteHeader.tsx:21` 去掉 `aria-label` 或改为包含 “Menu” 的文字；Esc/外部点击关闭需要少量 JS，是否值得做由设计决定（约束里不鼓励不必要的 JS）。

**L3. `/work/` 列表缩略图用 `object-fit: cover`，mobile 下裁切明显**
- `/work/` 的 `.work-entry-image` 在 desktop 是 16:10（3:2 原图裁约 6%），mobile 是 4:5（3:2 原图左右各裁掉约 23%，16:9 的 Dr. LeWinn's 裁得更多）。约束只要求案例 lead/gallery 用 `contain`，所以这不违规，但需要设计确认是否接受。
- 截图：`09-work-mobile-entry-cover-crop.jpg`
- 位置：`app/globals.css:56`、`:118`、mobile 断点 `.work-entry-image { aspect-ratio: 4 / 5 }`。

**L4. 联系邮箱仍是缺省值**
- 所有页面的 `mailto:hello@cheese.studio`，因为本次构建（按任务要求）没设 `NEXT_PUBLIC_CONTACT_EMAIL`（`app/_data/site.ts:37`）。已在 HANDOFF U5 中，列出只是提醒上线构建时必须带上。

**L5. 信息项（无需修）**
- 每页检测到 3 个 `scroll`/`wheel` listener。`app/` 内没有任何 `addEventListener`，来源是 vinext / React runtime（推测为 scroll restoration），不违反“不加 scroll listener”的约束。
- 首页 full-page 截图中 “Selected relationships” 列表和 services 区是空白的（`11-home-desktop-fullpage-reveal-artifact.jpg`）。原因是 `.home-reveal` 用 `animation-timeline: view()`，full-page 截图时视口外元素停在 `opacity: 0`。**真实滚动下实测正常显示**（`10-home-desktop-reveal-real-scroll.jpg`，进入视口的条目 opacity 逐步到 1）。不支持 scroll-driven animation 的浏览器（Firefox / 旧 Safari）的表现**未测**。
- 每页 header 与 footer 的 logo `alt` 都是 “First Rec.”（重复但合理）；`/about/` 的 `icon.svg` 是 `alt=""`（装饰图，合理）。
